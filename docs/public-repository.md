# 公开代码与私有运维资料分开维护

公开仓库提供可复用的应用与操作方法，私有配置库保存某个实例的具体情况。
运维信息即使不是密钥，也会帮助外部人员识别入口、内部路由和恢复路径。

## 哪些内容可以公开

- 应用代码、数据库迁移、依赖锁文件和使用合成数据的测试。
- 使用 `accounts.example.com` 的域名示例、示例 Compose/Nginx/SSH/续期配置。
- 安全合同、操作顺序、验收标准和不含真实实例值的故障处理方法。
- 上游软件的版本、发行校验和和安全修复依据；这些不是生产镜像 ID。

示例端点使用 RFC 5737 文档保留地址，Compose 使用另行选取的示例私网网段。
它们不表示真实部署，也不能未经调整直接覆盖任何现有环境。

## 哪些内容只保存在私有侧

- 真实域名、公网 IP、SSH 别名/端口、私网接口/网段、代理与备份节点关系。
- 实际部署、Secret、回退与离线恢复材料的路径。
- 实例版 Compose、Nginx、SSH、续期 unit，以及固定实例边界的发布/身份准备脚本。
- 原始验证记录、容量和保护资产清单、端口/路由/权限证据。
- 发布清单、实际镜像 ID/摘要、证书时间和恢复演练记录。

密钥仍由 Secret 文件或离线介质保管，不因配置库私有就把私钥或密码提交进去。
私有运维资料也不得放入公开 Issue、PR 附件、CI 日志、Release 资产或镜像层。

## 本地工作和长期归档

本地私有资料统一放入 Git 与 Docker 均忽略的 `.local/private-ops/`。
发布打包器只收集明确列出的公开目录/文件，不收集 `.local/`。
不要把真实配置放在 `docs/`、`infra/` 或 `scripts/` 后仅依赖文件名暗示其私有。

实例配置、原始历史、验证证据和未完成验收事项由独立私有运维库保管。
本地忽略目录用于工作与恢复，不代替私有库及独立备份。密钥和业务备份仍不提交任何 Git 仓库。
既有服务器以已部署的实例配置和发布记录为准，不直接拉取公开示例覆盖生产。

新增实例时，先在私有侧定制域名、目录、路由与网段，再同步调整示例发布器的精确校验。
保留 Linux/root/源地址检查、单 IP 代理信任、固定 SSH 命令、权限与禁止覆盖检查。
只更新应用时，也要通过私有部署流程集成和验收，不把公开示例当成当前实例配置。

## 发布前检查三个面

1. **当前文件**：检查待提交差异中的实例值、路径、主机标识、原始证据及任何凭据。
2. **Git 历史**：删除当前文件不会删除过去的提交；检查所有需要公开的分支和标签。
3. **衍生产物**：独立检查 Release、Actions 产物、容器镜像、Issue/PR 和已分享附件。

发生过公开暴露时，在隔离副本中清理历史；是否临时转私有由仓库所有者决定。
历史重写、强制推送、仓库可见性和远端资产删除均需由仓库所有者明确批准并协调协作者。
历史清理无法收回他人已有的克隆或分叉；若发现真正凭据，先撤销/轮换对应凭据。
仅发现拓扑信息时，不把无关密钥轮换、SSH 改端口或生产改网段作为自动操作。

历史重建后，已有克隆应重新克隆干净历史；不要合并旧分支或用 `--all`/`--mirror` 推回旧引用。
有未提交工作时先另存补丁或工作目录，再将必要改动应用到新克隆并重新检查；不要直接丢弃本地工作。
分支/标签历史清理与 GitHub 旧 SHA 缓存是两件事，后者须单独核查并按 GitHub 支持流程处理。

参考：[GitHub 历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)、[RFC 5737](https://www.rfc-editor.org/rfc/rfc5737)、[RFC 2606](https://www.rfc-editor.org/rfc/rfc2606)。
