# 实施阶段与交付边界

需求依据：[产品与技术规格](../gmail-account-manager-spec.md)。
阶段 0—4 的应用能力已经实现，当前 Alembic head 为 `0003`。
每个实例的部署状态、测试结果和未完成事项在私有台账维护；公开计划不替代上线验收。

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| 0 工程骨架 | 前后端、数据库模型、迁移、Compose、CI、生成客户端 | 空库迁移、失败启动门禁、构建、容器运行 |
| 1 认证 | 管理员 CLI、Argon2id、TOTP/恢复码、Session、CSRF、限流、AES-GCM | MFA 限权、轮换/撤销、加密失败、日志脱敏 |
| 2 账号核心 | CRUD、规范化、辅助邮箱、标签、密码访问、乐观锁 | 409 冲突、白名单响应、软删除恢复 |
| 3 管理体验 | 统计、服务端查询/分页/排序、批量、辅助邮箱、闲置锁定 | 统计口径、事务、日期边界、晚到响应隔离 |
| 4 迁移与运维 | CSV、Session/审计/设置、加密备份、异地取回和恢复 | 10 MiB、事务、保留策略、隔离恢复 |
| 5 实例上线 | 私有配置、HTTPS、加固、正式备份和恢复证据 | [25 项标准](acceptance-matrix.md) 与实例私有门禁 |

## 已确定的范围

P0 包含单条软删除恢复、基础已删除记录入口、辅助邮箱和 Session 管理。
完整回收站/批量恢复、增强设备管理和图表、加密敏感导出、密钥轮换命令、深色模式、PWA、WebAuthn 属于 P1。
不增加公开注册、多用户、OAuth 或 Google API。

## 需要保留的兼容合同

- `0002` 增加预会话、限流及加密待绑定 TOTP；认证状态在 PostgreSQL 事务锁下串行处理。
- 账号 API 复用完整认证；敏感操作另外检查最近重新验证；业务失败整批回滚。
- 阶段 3 列表从数组改为分页对象，客户端从 OpenAPI 生成；现有默认仍含归档、不含删除。
- `0003` 增加 CSV 确认凭据与可空闲置设置；不改写 `0001/0002`。
- CSV、批量与人工修改共用 row_version、加密、关联和审计规则。
- 恢复只有 CLI；切换到新库要单独确认，不用降级或覆盖旧库冒充恢复。

验收入口和证据分类见 [验收指南](validation.md)；应用测试不等于某个实例已经上线。
