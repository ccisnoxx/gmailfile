# 用 CSV 迁移账号

进入“安全设置 → 迁移与运维”。导入前先重新验证管理员密码；无需下载敏感数据。

## 先预览，再确认同一份文件

1. 选择 `.csv`，选重复策略（默认 `skip`），上传预览。
2. 标准列名自动映射；非标准列按“第 N 列”手工映射。修改映射后重新预览。
3. 查看新增、更新、跳过数量及逐行错误，再勾选确认并提交。

API 接受 `Content-Type: text/csv` 的原始字节，而非 multipart，因此不创建上传临时文件。
入口按实际接收字节限制 **10 MiB**（配置可调低），单次最多 **10000 条记录 / 256 列**；
后一限制在解析边界约束单事务和逐行响应的内存，避免很多短行/空列在10 MiB内生成数百万对象，较大迁移请拆分；UTF-8、UTF-8 BOM、CRLF/LF/CR、CSV 引号、逗号和引号内换行由标准 CSV 解析器处理。
不接受 UTF-16/GBK、NUL、引号结构错误或列数不一致；请先另存为 UTF-8 CSV。

前端只在内存保留文件；退出、锁定、隐藏或离开导入页即清除。服务端只在请求内存解析，
两次请求间不保存原文件，不在预览中返回密码、手机号、备注、原始表头或原始行。
列序号从 1 展示；错误行号按**逻辑记录**计数（表头为第 1 行，引号内换行不增加记录号）。

服务端生成 10 分钟、绑定当前 Session 的一次性确认凭据，保存文件 SHA-256、最终映射、策略、目标 ID/row_version，
不保存 CSV 内容。提交重传文件并只提供凭据 ID；服务端核对内容、重新解析校验、重新匹配数据库，
不接受客户端预览结论。重新验证轮换 Secret 不改变 Session ID；换 Session 必须重新预览。
成功提交消费凭据，重复使用拒绝。摘要用于两阶段内容绑定，不是保存密码的哈希方案。

## 重复和并发规则

- 规范化与普通账号 API 相同，数据库软删除记录也占用地址。
- `skip`：跳过数据库已存在记录；文件内第一条地址生效，后续规范化重复行跳过。
- `update`：更新数据库已有未删除记录，新地址新增；文件内仍第一条生效、后续重复跳过。
- `error`：文件内或数据库中任一重复均拒绝整批。
- 软删除记录可以 skip，不能由 update 隐式恢复；先在账号页面明确恢复后重新预览。
- 预览后主记录或关联目标的 ID/row_version 变化、原新地址被他人创建，提交返回冲突。
- update 调用既有账号 patch/CAS、AES-GCM、关联、标签及审计服务。单请求事务内写入全部账号；
  校验/冲突失败回滚全部账号、标签及成功审计，没有部分成功。
- 错误只返回 `{row, field, reason}`；不回显输入值。网络断开、500 或未知错误意味着**结果未知**，
  先检查账号和审计，再由用户决定下一次操作；客户端不重放提交。

## 字段、空值和关联

标准列：`account_no,gmail_email,password,registered_at,recovery_email,recovery_account,phone,status,two_factor_status,last_login_at,last_verified_at,password_changed_at,purpose,tags,notes`。
时间必须是带时区的 ISO 8601，最终按 UTC 保存；不接受模糊本地时间。

- 新账号必须有 Gmail、非空密码和辅助邮箱；空/未映射注册时间取**预览时**时间，状态默认 `pending_verification`，二步验证默认 `unknown`。
- update 不映射的字段保留；password 未提供或空字符串均保留旧密文，不允许用掩码替换密码。
- update 映射为空的注册时间/状态/二步验证拒绝；可空的手机号、备注、用途和三个可空时间则清空。
- `account_no` 留空由数据库生成。填写时只允许与规范化地址匹配的已有 `GM-000001` 编号；不能为新账号指定编号。
- `tags` 使用 `|` 分隔，名称 trim、去重，最多 100 个、每个不超过 50 字符；映射后替换整组，空值清空，未映射保留。缺失标签在同一事务内创建。
- `recovery_email` 始终是外部邮箱文本，即使与已有账号地址相同也不自动关联。
- `recovery_account` 明确按已有 GM 编号或规范化邮箱解析关联；目标必须存在且未删除，且不是自身/同一主邮箱。
  不解析本批待新建账号，先导入目标、再单独导入关联，避免顺序歧义。
- 两种辅助方式至多填一种；只要映射其中任一列，两列一起构成替换值，不能全部为空。两列都未映射时 update 保留原关联。

## 普通导出不会下载敏感字段

选择以下一种范围：

- **全部未删除（含归档）**：不使用当前筛选。
- **当前筛选的全部结果**：复用列表全部条件、排序、UTC 半开日期、归档与 deleted=true 语义；忽略页码/每页条数，不限于第一页。

固定白名单：编号、Gmail、注册时间、辅助邮箱、状态、二步验证状态、用途、标签、最后登录/验证/密码修改时间、归档/删除/创建/更新时间。
不包含密码、手机号、备注、TOTP、恢复码、管理员或 Session 数据。密码修改时间是时间戳，不是密码。

导出带 UTF-8 BOM 和标准 CSV 转义。可能被电子表格识别为公式的 `= + - @` 前缀（含前置空白）及控制前缀加单引号，
优先保证电子表格安全，不承诺无损往返导入。文件名由服务器生成 UTC 时间戳，如 `gmail-accounts-2026-11-24T160000Z.csv`；每次生成记录审计。
导出采用 `REPEATABLE READ READ ONLY` 快照事务、数据库服务端游标分批读取非敏感列与标签，并通过 `StreamingResponse` 逐批流式输出，避免数万级以上导出一次性占用大量内存。
带密码的加密导出仍属 P1，没有明文敏感下载替代接口。
