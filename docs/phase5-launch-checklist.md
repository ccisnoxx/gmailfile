# 实例上线与回退清单

复制到私有配置库后填写；本页是流程，不是授权或已经完成的上线记录。

## 执行前确认

- [ ] 明确本次主机、入口、域名、发布版本、目录、网络、端口和每个拟修改对象。
- [ ] 核对现有健康、容量与保护对象，保存原配置/符号链接/不存在状态。
- [ ] 保存旧发布、实际镜像 ID、schema、数据与已验证备份。
- [ ] 私有 Compose/Nginx/SSH/续期配置与发布器精确检查一致，示例值已全部替换。
- [ ] 独立管理核查/恢复通道可用；共享服务改动和停写范围已获批准。
- [ ] 新 Secret 不复用合成测试值，现有 Secret 不重生成、不递归改权。

## 上线顺序

- [ ] DNS/HTTP-01 与 TLS 主机名/证书链通过，续期 dry-run 和专用 timer 分别核验。
- [ ] 锁文件构建、PG18 应用回归、依赖/镜像检查通过；同名发布不覆盖。
- [ ] 停本项目写入及调度，PG 健康后迁移；失败不启动候选 API。
- [ ] API 容器健康且宿主机回环 ready 通过，再原子激活静态发布。
- [ ] 用户在自己的 TTY 初始化管理员，通过 HTTPS 绑定 TOTP 并离线保存恢复码。
- [ ] 验证真实代理来源和伪造转发头不能绕过限流；不向正式管理员注入错误密码。
- [ ] 按 [25 项标准](acceptance-matrix.md) 验收；生产合成数据操作和清理须事先批准。
- [ ] 手工备份、异地取回、独立恢复通过，再启唯一 backup 服务。
- [ ] 首次正式自然调度单独留证；age 身份和全部数据密钥离线保管由用户确认。

## 失败与回退

TLS、资源、迁移、健康、代理信任、漏洞或备份/恢复门禁失败，停止受影响阶段并保留数据和证据。
不以容器健康代替真实入口，不以换旧镜像代替数据库兼容性判断。

同 schema 且旧应用兼容时，经确认使用旧发布回退；schema 不兼容则从备份恢复到新库，另行批准停写和配置切换。
首次上线没有旧版本时，只停本项目 API/backup 并撤回本次入口/续期变更，保留 PG、卷、Secret、证书和备份。
只处理本次独立临时资源；不使用 `down -v`、全局 prune 或递归清理。正式调度不列入验收收尾停止清单。

现场结果、失败状态、未完成事项及下一责任人写入私有台账。步骤见 [部署手册](production-deployment.md)。
